Session input redesign

Mockups of the follow-up box at the bottom of a session (Composer in web/src/session.tsx), drawn with the app's design tokens. They only use what the server already supports: a model and effort per prompt, up to 10 attached files, queued prompts that can be cancelled, and Stop.

Every direction shares one core change: the text, the files and the controls move into a single rounded card, with the controls on a toolbar along its bottom edge.

  • The send button only says Send or Queue. Stop sits in the header, far from the cursor.
  • Queued prompts show up in the transcript as normal bubbles with a chip, so they're easy to miss.

A. Unified card

recommended
  • The pattern ChatGPT, Claude, Cursor and most prompt-input kits share: one rounded card. The textarea starts at one line and grows to 40% of the viewport. No resize grip.
  • The toolbar holds attach (+), then model and effort pills that show their value: "Default" in grey, or a set value in the text colour. They apply to this prompt only.
  • The round send button is a small state machine: greyed out when empty, ↑ to send, ■ to Stop while the agent runs with nothing typed, and ↑ to queue once you start typing.
  • Queued prompts move out of the transcript into a tray docked to the top of the card, numbered, with edit and ✕. ✕ uses the existing cancel. There's no edit API, so edit cancels the prompt and puts its text back in the box.
  • Attachments show as thumbnails inside the card. Dropping files anywhere on the page outlines the card as the drop target.
  • The hint reads "⌘↵ to send". Enter keeps adding a new line, as it does today.

B. Card with a status strip

A + session state
  • A's card, with a thin strip docked to its top that always says what the session is doing, the way Codex and Cursor's agent panels keep the agent's state beside the input.
  • Running: the current step, the elapsed time, the cost so far and a Stop button (which, as today, also drops the queue), right where you're typing. The header's Stop can go.
  • Sandbox stopped: says plainly that sending wakes it, so a follow-up doesn't seem to hang while the sandbox boots. This replaces the dashed "Sandbox stopped" line in the transcript.
  • Done: the cost and time, plus the pull request when there is one. The queue tray stacks under the strip.
  • The send button stays a plain ↑ because Stop has its own place in the strip.

C. Compact until focused

more room for the transcript
  • At rest, one 44px pill with the placeholder, attach and send, and the current model and effort as quiet text. That's about half today's height, leaving more room for the transcript and diffs.
  • Click it, press / or start typing, and it opens into A's card with the full toolbar. It folds back when empty and blurred.
  • The catch: the controls are hidden until you focus the input, so they're harder to discover, and the box moves as it opens.

D. Queue or interrupt

add-on to A or B
  • While the agent works, sending offers two things: Queue (the default, as today) or Interrupt, which stops the turn and sends this prompt right away. LibreChat and Claude Code make the same split.
  • Interrupt cancels the running prompt with the existing DELETE …/prompts/{id}, not Stop (Stop also drops the queue), then sends. With other prompts queued, the new one would land behind them, so jumping the queue needs a small server change. ⌘↵ queues; ⌘⇧↵ interrupts.
  • A labelled split button suits this better than a bare icon, since what happens on send changes with the session's state.

Suggestion

Build A, with B's status strip on top. The card, the toolbar pills and the queue tray fix the problems in the screenshot. The strip moves Stop and the "Sandbox stopped" notice next to the cursor, which matters most in an agent app where turns run for minutes. D's Interrupt is cheap to add later. I'd skip C: hiding the model and effort controls costs more than the 40px it saves.

Patterns from the research

  • A single card holding the text, attachments and a bottom toolbar, with send at the bottom right, is the common layout across agent chat UIs and prompt-input component kits.
  • The send button works as a state machine: ready, sending, streaming (shown as Stop), error.
  • Queued follow-ups live in a separate tray above the input, where you can edit, cancel or reorder them, rather than in the message list.
  • Model and effort controls belong before send, next to the input, because their effect on cost and quality has to be chosen up front.
  • While a turn runs, apps either queue a new prompt or steer the agent with it, and some let you choose per message.
