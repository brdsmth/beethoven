Where people get lost

  • 1"Beethoven" and "member" go unexplained. Nothing says it runs coding agents, or what joining Payments means.
  • 2A password is the only way in, even when the server has a GitHub App they will connect a minute later anyway.
  • 3Before the app is set up, a member is shown the admin's Create the GitHub App form.
  • 4An empty prompt with no examples, and "Workspace" / "Seen by" choices they can't judge yet.
  • 5Points members to credential settings only admins can change.
  • 6An empty sidebar, even though their team already has sessions they could learn from.

Also

  • Someone who already has an account can't use a team invitation: it fails with "already has an account: sign in instead".
  • Expired or used links end in a dead end with no one to ask.
  • Admins get a bare URL to paste, with nothing that tells the recipient what it is.

Why a tour

What changes

  • A note that the invitee sees on their page (screen 1), for the personal touch.
  • A ready-to-paste message that says what Beethoven is, so the link isn't a bare token in Slack.
  • Preview their page shows the admin exactly what the invitee will see.
  • Later: team leads invite to their own team (today only admins can).

Needs

  • A note column on invites (≤ 280 chars).

Suggested order of work

  1. Explain on the way in: the invitation page's left side, the inviter's note and plain-words role. Front-end plus a few more fields on GET /api/auth/invite.
  2. Fix the dead ends: role-aware setup prompts for members, the expired-link page, and accepting a team invitation with an existing account.
  3. Get started checklist with the glossary, and the team's recent sessions in the sidebar. Needs onboarding state on the account.
  4. Welcome tour and first-session tips and starting points.
  5. Continue with GitHub on the invitation page: the biggest change, since sign-up today is email and password only.
