# Beethoven Phase 1.5: Real Agent Execution Plan

## Objective

Replace deterministic stub execution with real software engineering execution.

Current state:

- Event sourcing exists.
- Multi-project support exists.
- Agent templates exist.
- Agent instances exist.
- Inbox exists.
- Timeline exists.
- Task orchestration exists.
- Workspace abstractions exist.

Current limitation:

```text
PM -> Tasks -> Fake Execution -> Events
```

Desired state:

```text
PM
 ↓
Task
 ↓
Workspace
 ↓
Claude Code
 ↓
Git Changes
 ↓
Review
 ↓
Events
```

The goal of this phase is to make Beethoven genuinely useful for software development while preserving the existing architecture.

---

# Guiding Principle

Do not build an AI framework.

Build an orchestration system around existing coding agents.

Beethoven should orchestrate:

- Claude Code
- Codex
- Future coding agents

It should not attempt to replace them.

# Milestone 1

## Real Workspaces

Replace workspace stubs.

Current:

```text

```

Desired:

```text
workspace/

├── repo/
├── memory/
├── logs/
├── artifacts/
└── prompts/
```

Requirements:

- Create git worktree
- Create branch
- Store metadata
- Persist lifecycle events

Events:

```text
WorkspaceCreated
WorktreeCreated
BranchCreated
```

Acceptance Criteria:

- Worktree exists on disk
- Branch exists
- Events recorded

# Milestone 2

## Real tmux Runtime

Every agent instance receives a tmux session.

Naming:

```text
beethoven:<project>:<agent>:<task>
```

Examples:

```text
beethoven:sample:backend:123
```

Requirements:

- Create session
- Execute commands
- Capture output
- Persist logs

Events:

```text
TmuxSessionCreated
TmuxCommandExecuted
TmuxOutputCaptured
```

Acceptance Criteria:

```bash
tmux ls
```

shows active Beethoven sessions.

# Milestone 4

## Task Prompt Contract

Every task becomes a structured execution request.

Example:

```text
Project:
Sample

Task:
Implement OAuth login

Repository:
~/workspace/sample

Branch:
task/oauth-login

Requirements:
- Support Google
- Support GitHub

Constraints:
- Use existing auth architecture
```

Prompt should be generated by Beethoven.

Never handcraft prompts in orchestration code.

# Claude Code Strategy

Preferred:

Launch Claude Code inside tmux.

Example:

```bash
claude --dangerously-skip-permissions
```

Beethoven controls:

- workspace
- prompt
- lifecycle

Claude controls:

- coding

This minimizes custom orchestration complexity.

---

# Success Criteria

The phase succeeds when:

1. Create project.
2. Create initiative.
3. Generate tasks.
4. Assign backend task.
5. Beethoven creates worktree.
6. Beethoven launches tmux.
7. Claude modifies code.
8. Git diff is captured.
9. Review agent approves.
10. Task completes.
11. Timeline records everything.

At this point Beethoven transitions from:

```text
Agent Simulation
```

to:

```text
Software Organization Runtime
```

and becomes genuinely useful for daily engineering work.
